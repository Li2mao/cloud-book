## 相关知识解读

### Redis

Redis 是开源、内存型 KV 数据库，C 语言开发，速度快；支持持久化（RDB/AOF），可做缓存、分布式锁、计数器、消息队列等，支持 string、hash、list、zset 等多种数据结构。

#### 三种常见部署模式

1. **主从复制** 一主多从，主节点负责写，数据同步到从节点；从节点只读，分担读请求、备份数据。缺点：主挂了不会自动切换，写无法扩容。
2. **Sentinel（哨兵）** 基于主从，额外部署哨兵进程监控节点。主节点故障时自动选从升主，实现高可用。 ⚠️ 注意：仍然只有一个主节点，数据全量存储，**不能扩容写能力**。
3. **Redis Cluster（分片集群，原生集群）** 多主多从架构，一共划分 16384 个哈希槽，key 通过哈希算法分配到不同主节点，数据分片存放。

- 优点：读写都可以横向扩容，自带故障转移
- 缺点：跨槽位的多 key 命令有限制，运维更复杂

> 最小推荐：3 主 3 从

#### 持久化

- RDB：快照，保存某一刻全部数据，文件小恢复快，可能丢数据。
- AOF：记录每条写命令，安全性高，默认每秒落盘，文件更大。
- 同时开启时，重启优先加载 AOF。

一句话：RDB 是拍照，AOF 是记操作日志。

### PHP

**服务端脚本语言，本身只是解释器，不能独立监听端口接收网络请求。 **PHP-FPM（PHP FastCGI Process Manager）**：PHP 的 FastCGI 进程管理器，是 PHP 用来和 Nginx/Apache 配合的中间程序。

#### 简单流程

Nginx（L7 反向代理）收到用户请求 → 如果是 php 文件 → Nginx 把请求转发给 **php-fpm** → fpm 调用 php 解释器执行代码 → 把页面结果返回给 Nginx，再发给浏览器。

#### 要点

1. Nginx 只负责静态文件、转发请求，**不解析 PHP 代码**
2. php-fpm 维护一组 PHP 工作进程池，进程数量可以配置
3. 通信方式：`unix socket`（本机，快） 或者 `tcp ip:port`（跨机器）
4. 常见参数：`pm.max_children` 最大子进程数，控制并发

一句话总结： **PHP 是解释器，php-fpm 是管理 PHP 进程、接收 Nginx 请求的服务。**

### L4 四层负载均衡（传输层）

基于**IP + 端口**转发，看 TCP/UDP，不解析应用内容。

- 工作层级：传输层（TCP/UDP）
- 识别信息：源 IP、目标 IP、端口
- 代表：LVS、IPVS、Nginx stream、HAProxy mode tcp
- 特点：速度快、开销小；**看不到 HTTP 请求内容**，不能识别域名、url、cookie

### L7 七层负载均衡（应用层）

基于**应用协议内容**转发（HTTP/HTTPS）。

- 工作层级：应用层
- 识别信息：域名、URL、Cookie、请求头、路径
- 代表：Nginx http、HAProxy mode http、Ingress
- 特点：功能丰富，可以按路径 / 域名分流；需要解析协议，性能比 L4 低一点

> 一句话区分： L4：只管 “把包送到哪个端口”； L7：看懂 HTTP 内容，按网站域名、路径分发请求。

* 创建LB01容器
  * 先将原本的配置复制到/opt/lnmp/lb01和lb02目录下
  * 配置负载均衡到web01-03

```bash
docker run -d --rm -v /opt/lnmp/lb01:/data nginx:latest cp -r /etc/nginx/. /data
docker run -d --rm -v /opt/lnmp/lb02:/data nginx:latest cp -r /etc/nginx/. /data

cat /opt/lnmp/lb01/nginx.conf
# 注释掉http模块中的include命令，默认配置会抢80端口
# 在最后追加（这部分代码可以交给AI来写）
# 四层负载均衡 stream 块，和 http{} 同级
stream {
    upstream web_backend {
        server web01:80;
        server web02:80;
        server web03:80;
        # 默认策略就是 round_robin 轮询(rr)，不用额外写
    }

    server {
        listen 80;
        proxy_pass web_backend;
    }
}

# 下面的命令在lnmp文件夹下运行，因为有`pwd`
# 用`pwd`的好处在于，将这个镜像打包之后，路径依旧正确
docker rm -f lb01
docker run -d --restart=always \
-p 80:80 \
--name lb01 \
-v `pwd`/lb01:/etc/nginx \
--link web01:web01 \
--link web02:web02 \
--link web03:web03 \
nginx:latest
```

## 4.LB02负载均衡

* 创建两个php-fpm做测试，需要加到run.sh

``` bash

docker run -d --name php-fpm02 -v `pwd`/blog/www:/usr/share/nginx/html php:7.4-fpm
```

* 修改lb02，先修改配置文件

```bash
# 记得注释include
cat /opt/lnmp/lb02/nginx.conf
stream {
    upstream php_backend {
    	# php默认端口是9000
        server php-fpm01:9000;
        server php-fpm02:9000;
        # 默认策略就是 round_robin 轮询(rr)，不用额外写
    }

    server {
        listen 9000;
        proxy_pass php_backend;
    }
}

```

* 创建lb02，也是写到run.sh中

``` bash
docker run -d --name lb02 --restart=always \
-v `pwd`/lb02:/etc/nginx \
--link php-fpm01:php-fpm01 \

nginx:latest
```
