# 灰度发布（灰度更新）

简单说：**不是一次性全部更新所有 Pod，先更新一部分实例，观察业务是否正常，没问题再逐步全量更新，有问题立刻回滚**，是 K8s 里常用的发布策略。

> 和默认滚动更新区别： K8s 原生`rollout`滚动更新是**缓慢分批替换**；灰度一般是**单独保留一部分旧版本、一部分新版本，流量切一部分给新版本**，流量比例可控。

### 核心流程

1. 同时跑**旧版本 + 新版本**两组 Pod
2. 把一小部分流量分给新版本（比如 10% 流量）
3. 监控日志、报错、响应耗时
4. 稳定无异常 → 逐步加大流量，直到全部切到新版本
5. 发现 bug → 直接切回全部旧版本，风险很小

* 创建k8s的srv的服务

```b
# 会通过CoreDNS自动将myservice解析成功
$ kubectl create svc clusterip myservice --tcp=80:80
[root@master k8s-resource]# kubectl get svc
NAME         TYPE        CLUSTER-IP     EXTERNAL-IP   PORT(S)   AGE
kubernetes   ClusterIP   10.0.0.1       <none>        443/TCP   3d1h
myapp        ClusterIP   10.3.139.189   <none>        80/TCP    43h
```

* 分出一个窗口用于测试

```b
[root@master k8s-resource]# while true; do curl 10.3.139.189/etc/os-release; sleep 1;done

...............
<hr><center>nginx/1.28.0</center>
...............
```

* 创建一个k8s启动文件

```b
[root@master k8s-resource]# cat 14-deploy.yml 
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: myapp-deploy
  name: myapp-deploy
spec:
  replicas: 1
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec: 
      containers:
      - name: myapp
        image: nginx:1.28.0
        resources:
          limits:
            memory: "128Mi"
            cpu: "500m"
        ports:
        - containerPort: 80

# 启动
[root@master k8s-resource]# kubectl apply -f 14-deploy.yml 
```

* 编辑文件生成2.0

```b
[root@master k8s-resource]# kubectl edit deploy myapp-deploy
.........
      - image: nginx:1.29.0
.........
# 此时版本升级变成1.29.0
# 变化符合灰度策略
<hr><center>nginx/1.29.0</center>
```
